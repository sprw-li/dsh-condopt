## 一句话结论

**当前产品是「优化状态查看器 + 受控 CLI 控制台」，还不能宣称「参数可调、可完成一轮优化」。**
最大缺口不是命令数量，而是：面板有 ask、没有结果回填（tell）；「可调」没有区分当前值 / 默认值 / 待生效修改；
`condopt_view` 能返回摘要，却不能把用户带到同一个 run 的视图。

建议 v1 收敛为：**对话中的项目材料查看器 + 单 study、单批次、由用户确认的优化回合控制器**。

## 共识（三条）

1. 优化回合断在结果回填：面板有 ask/confirm/override/auto/step，**没有 tell 入口**。
2. `ask.n` + `confirm.n` + `override.algorithm/params` 不足以证明「参数可调」；缺的是参数语义
   （改的是哪个 run、当前有效值、spec 默认值与实际值的区分、从哪一批生效、是否真的生效）。
3. 只读 `condopt_view` 适合模型诊断，但不等于「调出视图」：工具卡不能带 root/run 打开面板定位同一 study；
   反过来，直接给 agent 通用 exec 或自动 override/step 风险大于收益。

## 理事会裁决（分歧处）

| 议题 | 裁决 |
|---|---|
| agent 能否直接 `tell` | 不能自动落盘。agent 可整理观测、生成草稿；写入必须用户确认，且**宿主侧重新校验** run/参数/批次/状态。v1 甚至可以不新增任何 agent 写工具 |
| 视图：完整还原 dashboard vs 降级为跳转 workbench | 都不走。**摘要卡为默认视图，完整报告降级为「可重新生成的静态快照」**；深度交互探索留给 workbench，但 workbench 不是本插件的必需 fallback |
| shadow DOM 注入 | 只解决样式隔离，不等于安全沙箱/可交互。建议改 `sandboxed iframe`（禁脚本/表单）+ 外部文本摘要兜底；不为恢复图表交互而重写一套渲染 |
| 与 workbench 的关系 | 靠**产品分工**独立而非「不 import」：dsh-condopt 答「现在到哪了、下一步为什么、我确认后发生了什么」；workbench 负责深度可视化探索 |
| 发布形态 | 单文件无构建链不是主要风险；主要风险是**任意位置安装后的 root 解析、slot 漂移静默降级、缺少诊断页**。不引入大型构建，但当闭环代码增长时应拆源码 + 生成同款零依赖产物 |

## 最终建议（按价值排序，原文顺序）

1. **先补齐单批次闭环，并重新定义「参数可调」**：把参数页拆成「当前 study / 下一批参数 / 算法覆写 / 新建 study」四块；
   超参草稿只标用户真正改过的字段，执行前预览最终生效集合；切 run 作废旧草稿。
   最低验收不是「控件更多」，而是：**能无歧义地确认一次修改 → 下一批确实按该修改生成 → 回填无需回终端 → 可审计**。
2. **agent 先补「视图交接」**：工具卡加「在条件优化面板中打开」，带 root/run 定位同一 study；写能力只做「草稿、不执行」。
3. **视图收敛为静态快照 + 文本摘要**（大 study 不重传重画、加体积上限、可访问性兜底）。
4. **用产品分工写进 README 首屏与 DESIGN**，明确不做清单（跨 run 图形比较、自由图表配置、多 run 调度、agent 自动 step）。
5. **独立发布先补设置/诊断页**：配置并保存 root 与 python，显示 root 来源、CLI 能力、版本、DSH 兼容范围与已降级入口；
   每次跳过注册都要留可查原因；README 自包含、用独立仓库可用的绝对链接。
6. **只再做一件事**：交付一条真实的单 study、单批次垂直切片——
   `agent 工具卡打开指定 run → 看到当前状态与参数来源 → 确认 diff 并 ask → 面板内按 CLI 契约回填 tell → 视图与决策记录更新 → 显示执行回执`。

## 评审自身标注的前提与【推断】

- condopt dashboard 渲染器与 workbench 内部实现未完整覆盖，因此「脚本图表依赖」「交互缺失」属**【推断】**；
  不影响「静态快照、不追完整交互」的取舍。
- `tell` 是否能在 `/api/exec` 的零写入策略下真实持久化、当前有效算法参数能否读取——附件不足以确认，属**垂直切片的前置条件**。
  不能用未经核实的 `{run, observations}` 契约直接实现。
- 结论不以现有验收通过数推断产品闭环已完成。
- 不采用未经核实的字节数 / `package.json` files 断言，也不采用「shadow DOM 使 document 事件一概失效」这类不准确表述。

## Lead 对【推断】项的本地核实（2026-11-20，供后续实现参考）

- `tell` 真实可用：`py -3 scripts/run_condopt.py tell --run <r> --results <file> --json` 是既有 CLI 契约（`cli.py:1288-1292`），
  接受 JSON/JSONL/CSV 文件路径；因此面板要回填只需把用户粘贴的内容写成 tmp 文件再调用，**不需要新 payload 契约**。
- 「零写入」只针对有 `--out` 的导出类命令；`tell` 本身就是要写 run 真源的显式写操作，属于用户点击才会发生。
- 当前生效算法参数可从 `report --json` / `config.json` 读取，能在面板区分「当前值 / spec 默认值」。
